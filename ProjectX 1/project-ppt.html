Trackify

Smart Society Management System

A full-stack web application for modern residential community management

Web Application  |  Next.js  |  Supabase
Slide 2 / 30

Problem Statement

  • Residential societies rely on manual, paper-based processes for maintenance, payments, and communication.
  • Residents lack a unified platform to report issues, book amenities, or track payment status in real time.
  • Security management for visitor entry is fragmented and prone to human error.
  • Society administrators have no centralized dashboard for analytics, fund tracking, or member oversight.
  • Emergency situations such as SOS alerts have no digital escalation mechanism in place.
  • Absence of AI-assisted tools leads to slow issue classification and poor service matching.
Slide 3 / 30

Objectives

  • Build a centralized digital platform for end-to-end society management accessible via web and mobile browsers.
  • Enable residents to report issues, pay maintenance dues, and book amenities seamlessly.
  • Provide administrators with real-time analytics, fund management, and member oversight tools.
  • Integrate AI features for issue classification, service matching, and an intelligent assistant (ARIA).
  • Implement a secure visitor management system with OTP-based entry verification.
  • Deliver SOS emergency alerts with SMS notifications to designated contacts.
Slide 4 / 30

Existing System

  • Most societies use WhatsApp groups and physical notice boards for announcements and communication.
  • Maintenance payments are collected manually via cash or bank transfer with no digital record.
  • Visitor entry is managed through physical registers maintained by security guards.
  • Issue complaints are submitted verbally or via handwritten forms with no tracking mechanism.
  • Amenity bookings are handled informally, leading to double-booking and disputes.
Slide 5 / 30

Limitations of Existing System

  • No real-time visibility into issue status, payment dues, or visitor logs for residents or admins.
  • Manual processes are error-prone, time-consuming, and difficult to audit or trace.
  • Communication is scattered across multiple channels with no single source of truth.
  • No role-based access control — all information is accessible to everyone or no one.
  • Lack of data analytics prevents informed decision-making by the managing committee.
  • Emergency situations cannot be escalated digitally, delaying response times.
Slide 6 / 30

Proposed System

  • Trackify is a full-stack web application providing a unified platform for all society operations.
  • Role-based dashboards for residents, guards, secretaries, and chairpersons with tailored views.
  • Integrated payment gateway (Razorpay) for online maintenance collection with automated notifications.
  • AI-powered modules for issue classification, smart service matching, and a conversational assistant.
  • OTP-based visitor management system with digital pass generation and guard verification.
  • Real-time analytics, society fund tracking, and community engagement features built in.
Slide 7 / 30

Key Features

  • Issue reporting and tracking with AI-based auto-classification and status updates.
  • Online maintenance payment via Razorpay with receipt generation and due-date reminders.
  • Amenity booking system with calendar-based slot management and conflict prevention.
  • Visitor management with OTP verification, digital passes, and guard-side approval.
  • SOS emergency alert system with SMS dispatch to registered emergency contacts.
  • ARIA — an AI assistant for resident queries, notices, and society information.
Slide 8 / 30

System Architecture Overview

  • Three-tier architecture: Presentation Layer (Next.js), Application Layer (API Routes), Data Layer (Supabase).
  • Client-side rendering with React for interactive UI; server-side API routes handle business logic securely.
  • Supabase provides PostgreSQL database, authentication, real-time subscriptions, and row-level security.
  • External integrations: Razorpay for payments, Twilio/SMS gateway for SOS alerts, OpenAI for AI features.
  • Deployed on Vercel with edge functions for low-latency API responses globally.
  • Progressive Web App (PWA) support enables mobile-like experience without a native app.
Slide 9 / 30

Technology Stack

  • Frontend: Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS, Framer Motion.
  • Backend: Next.js API Routes (serverless), Node.js runtime on Vercel Edge.
  • Database: Supabase (PostgreSQL) with Row Level Security and real-time listeners.
  • Authentication: Supabase Auth with email/password and session management.
  • Payments: Razorpay SDK for order creation, payment capture, and webhook verification.
  • AI: OpenAI API for ARIA assistant, issue classification, and smart service matching.

Frontend Technologies

  • Next.js 14 App Router enables file-based routing, layouts, loading states, and server components.
  • React 18 with hooks (useState, useEffect, useCallback) for reactive, performant UI components.
  • TypeScript enforces type safety across all components, API calls, and data models.
  • Tailwind CSS provides utility-first styling with responsive design and dark mode support.
  • Framer Motion powers smooth animations, page transitions, and micro-interactions.
  • Lucide React supplies a consistent, accessible icon library used throughout the interface.
Slide 11 / 30

Backend Technologies

  • Next.js API Routes serve as serverless backend endpoints, eliminating the need for a separate server.
  • Supabase client library handles all database queries, authentication, and real-time subscriptions.
  • Razorpay Node SDK manages order creation, payment verification via HMAC-SHA256 signature validation.
  • OpenAI API integration powers AI features including ARIA chatbot, issue classification, and service matching.
  • SMS notifications for SOS alerts are dispatched via a third-party SMS gateway API with input sanitization.
  • Rate limiting is implemented on sensitive endpoints (e.g., ARIA) to prevent abuse and control API costs.
Slide 12 / 30

Database Design

  • PostgreSQL hosted on Supabase with normalized relational schema and foreign key constraints.
  • Core tables: society_members, issues, payments, amenity_bookings, visitor_passes, notices, polls.
  • Row Level Security (RLS) policies ensure users can only access data belonging to their society and role.
  • Indexes on frequently queried columns (user_id, status, created_at) for optimized read performance.
  • Real-time subscriptions on issues and payments tables enable live dashboard updates without polling.
  • Seed SQL scripts provided for amenities, payments, and analytics data to support development and demos.

System Modules Overview

  • Authentication Module: Registration, login, forgot/reset password, and society onboarding.
  • Issue Management Module: Report, track, classify, and resolve maintenance complaints.
  • Payment Module: Online maintenance payments, history, receipts, and admin approval workflow.
  • Visitor Management Module: Pass creation, OTP verification, guard dashboard, and cancellation.
  • Amenity Booking Module: Slot-based booking, conflict detection, and booking history.
  • AI & Communication Module: ARIA assistant, SOS alerts, community chat, notices, and polls.
Slide 14 / 30

Module 1: Issue Management

  • Residents submit maintenance complaints with title, description, category, and optional photo attachment.
  • AI-powered classification endpoint auto-assigns issue category (plumbing, electrical, civil, etc.) on submission.
  • Clean-description API rewrites poorly formatted complaints into professional, actionable language.
  • Issues are tracked through statuses: Open, In Progress, and Resolved with timestamped history.
  • Admin dashboard displays all open issues with priority indicators and assignment capabilities.
  • Residents receive status update notifications when their issue progresses or is resolved.
Slide 15 / 30

Module 2: Payment System

  • Residents view pending maintenance dues with due dates and amounts on their payment dashboard.
  • Razorpay integration creates a secure payment order server-side and opens the checkout modal client-side.
  • Payment verification uses HMAC-SHA256 signature validation to confirm transaction authenticity.
  • Successful payments update the database record and trigger an email/notification receipt to the resident.
  • Admin panel shows all pending and completed payments with export and approval capabilities.
  • Smart banner alerts residents when a payment is due within 7 days for proactive reminders.
Slide 16 / 30

Module 3: Visitor Management

  • Residents pre-register expected visitors with name, contact number, purpose, and expected arrival time.
  • System generates a unique OTP and digital visitor pass upon successful registration.
  • Guard dashboard displays all active passes; guards verify entry by validating the OTP at the gate.
  • Residents can cancel a pending visitor pass before the visitor arrives via the my-passes view.
  • All visitor activity is logged with timestamps, enabling a complete audit trail per flat.
  • Input validation ensures only valid Indian mobile numbers are accepted for visitor contact fields.

User Roles & Permissions

  • Resident: Can report issues, pay dues, book amenities, register visitors, use ARIA, and send SOS alerts.
  • Guard: Accesses the guard dashboard to verify visitor OTPs and monitor active passes at the gate.
  • Secretary: Manages payment approvals, member records, notices, and society fund transactions.
  • Chairman / Chairwoman: Full admin access including analytics, map view, polls, and all module oversight.
  • Role assignment is stored in the society_members table as a badge field and enforced via RLS policies.
  • Dashboard greeting and quick-action cards adapt dynamically based on the authenticated user's role.
Slide 18 / 30

Data Flow Diagram (Described)

  • User authenticates via Supabase Auth; session token is stored client-side and sent with every API request.
  • Client sends form data to Next.js API Route; the route validates input, applies business logic, and writes to Supabase.
  • For payments: Client calls /api/razorpay/create-order, Razorpay returns order ID, client completes payment, then /api/razorpay/verify-payment confirms the signature.
  • For AI features: Client sends prompt to /api/aria or /api/classify-issue; the route calls OpenAI API and returns the structured response.
  • For SOS: Client sends emergency data to /api/send-sos-sms; the route sanitizes input and dispatches SMS via gateway.
  • Supabase real-time listeners push database changes directly to subscribed client components without page refresh.

System Workflow

  • New society registers via the society-register page; admin account is created and society config is initialized.
  • Residents register with flat number and email; admin approves and assigns the appropriate role badge.
  • Upon login, users land on a role-aware dashboard displaying relevant stats, notices, and quick actions.
  • All CRUD operations flow through typed API routes with server-side validation before database writes.
  • Notifications (payment due, issue update, visitor arrival) are delivered via in-app banners and email.
  • Admin reviews analytics, manages funds, and exports reports from the dedicated admin panel.

Security Features

  • Supabase Row Level Security (RLS) ensures database queries are scoped to the authenticated user's society.
  • Razorpay payment verification uses HMAC-SHA256 signature validation to prevent payment tampering.
  • All API route inputs are validated and sanitized server-side before processing or database writes.
  • Rate limiting on the ARIA endpoint prevents abuse and controls third-party API cost exposure.
  • Indian mobile number validation on SOS and visitor endpoints blocks malformed or malicious inputs.
  • Environment variables store all secrets (API keys, DB URLs); no credentials are exposed client-side.
Slide 22 / 30

Performance Optimization

  • Parallel data fetching using Promise.all on the dashboard reduces total load time significantly.
  • useCallback memoization prevents unnecessary re-renders of data-fetching functions in React components.
  • Next.js Inter font loaded with display: swap and preload: true to eliminate flash of unstyled text.
  • Viewport meta tag sets maximumScale: 1 to prevent iOS zoom on input focus, improving mobile UX.
  • Supabase queries use head: true for count-only requests, avoiding full row data transfer.
  • Vercel Edge deployment ensures API routes execute close to the user's geographic location.

Challenges Faced

  • Designing RLS policies that correctly scope data per society without impacting query performance.
  • Ensuring Razorpay payment verification is tamper-proof while handling edge cases like network failures.
  • Managing real-time Supabase subscriptions without memory leaks across multiple dashboard components.
  • Preventing circular re-renders when combining useCallback, useEffect, and real-time listeners in React.
  • Balancing AI API call costs with user experience — rate limiting ARIA without degrading responsiveness.
  • Achieving consistent mobile UX across iOS Safari and Android Chrome with PWA constraints.
Slide 26 / 30

Solutions Implemented

  • RLS policies were iteratively tested with Supabase's policy editor and seed data to validate correctness.
  • Payment verification implemented server-side with crypto HMAC comparison, never exposed to the client.
  • Supabase subscriptions are cleaned up in useEffect return functions to prevent memory leaks on unmount.
  • useCallback with stable dependency arrays prevents infinite re-render loops in data-fetching hooks.
  • IP-based rate limiting with an in-memory map throttles ARIA requests per client without external infrastructure.
  • PWA viewport and manifest configuration tested on real devices to resolve iOS-specific rendering issues.
